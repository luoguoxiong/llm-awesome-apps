## 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是一种把外部知识检索与大模型生成结合的架构。
核心流程是：用户提问后，先从知识库中检索相关文档片段，再把片段作为上下文交给大模型生成回答。
RAG 的价值在于：无需重新训练模型即可注入私有知识、降低幻觉、并可通过引用来源提升可解释性。

一个典型的 RAG 管线包含四个阶段：

1. 摄取（Ingest）：把原始文档切分为块（chunk），为每块生成向量并写入索引
2. 检索（Retrieve）：把用户问题向量化，从索引中召回最相关的片段
3. 重排（Rerank）：对召回片段做精细化排序，过滤噪声
4. 生成（Generate）：把 top 片段拼入提示词，交由 LLM 生成最终回答

## 混合检索：关键词 + 向量

单一检索通道各有盲区：

- 关键词检索（BM25 等）擅长精确词面命中，例如产品型号、专有名词、错误码；
  但无法理解同义改写（"怎么退货" vs "退款流程"）。
- 向量检索擅长语义相似，能跨词汇差异召回；但对低频专有名词、数字与符号不敏感。

混合检索（Hybrid Search）同时跑两条通道，再融合结果，取长补短。常见融合策略：

- 加权分数融合：把两通道分数归一化后加权求和，权重需要调参
- 倒数排名融合（RRF, Reciprocal Rank Fusion）：每个文档的融合分数等于
  Σ 1/(k + rank)，k 通常取 60。RRF 只依赖名次而不依赖分数分布，无需调参、
  对不同打分体系天然免疫，是最常用的默认方案。

## BM25 关键词检索原理

BM25 是经典的概率检索模型，得分由三部分构成：词频（TF）、逆文档频率（IDF）
与文档长度归一。公式可概括为：

score(q, d) = Σ IDF(qi) · TF 饱和项 · 长度归一项

- TF 饱和：词频增益递减（参数 k1 控制，常取 1.5），避免关键词堆砌刷分
- 长度归一：长文档天然更容易命中查询词，参数 b（常取 0.75）抑制这种偏置
- IDF：罕见词权重高，常见停用词权重趋近于零

## 向量检索与嵌入模型

向量检索把文本映射为稠密向量（embedding），用余弦相似度等度量语义距离。
嵌入模型（如 text-embedding-3、bge-m3）在大规模语料上对比学习训练，
使语义相近的文本在向量空间中靠近。工程要点：

- 查询与文档要用同一个嵌入模型编码，否则向量空间不一致
- 中文场景建议用中文优化的嵌入模型，或用双字滑窗做简单分词兜底
- 向量维度越高表达能力越强，但索引与计算成本随之上升

## LLM 相关性重排（Rerank）

召回阶段的检索器追求高召回率，难免混入噪声片段。重排器（Reranker）在召回后
做精排：把"问题 + 候选片段"成对输入模型，逐对打分。两类常见实现：

- 专用交叉编码器（如 Cohere Rerank、bge-reranker）：效果好，需要额外服务或 Key
- 用 LLM 做相关性评估：让模型对每个候选输出"相关/不相关"或按相关度排序，
  零额外依赖，本应用即采用此方案（批量单次调用，逐片段输出 yes/no）

重排的收益：上下文窗口有限时，把最相关的片段排在前面能显著提升回答质量；
无关片段混入会诱导模型跑题甚至产生幻觉。

## 通用知识兜底（Fallback）

当知识库中没有与问题相关的片段时，强行 RAG 会让模型"编造"基于无关上下文的回答。
更好的做法是兜底：检测到无相关片段后，直接用模型的通用知识回答，并明确告知
用户本次回答未参考知识库文档。这样既保留了知识库的精确性，又不牺牲闲聊与
通用问题的体验。

## RAG 常见失败模式

- 检索 miss：问题与文档表述差异过大，召回为空或全不相关 → 需要兜底或改写查询
- 分块不当：块太大导致噪声稀释、块太小丢失上下文 → 段落边界优先 + 适度重叠
- 上下文污染：多个相似但矛盾的片段同时进入上下文 → 依赖重排与去重
- 知识过期：文档更新后索引未同步 → 增量摄取与按来源删除
- 评测缺失：没有量化指标就无法判断检索与生成各自的质量 → 命中率 + 忠实度双维度评测

## LangGraph 与 Agentic RAG

LangGraph 把 LLM 应用建模为状态图（StateGraph）：节点是处理步骤（如检索、重写、
生成），边是控制流，支持条件路由与循环。经典模式如 "检索 → 相关性评估 →
（不相关则）查询改写 → 再检索 → 生成"。

Agentic RAG 进一步把检索变成 Agent 的工具：由 Agent 自主决定是否检索、检索几次、
何时停止。相比固定管线，Agentic RAG 在复杂多跳问题上更灵活，代价是调用成本
与延迟上升。

## LLM Agent 核心概念

LLM Agent 是以大模型为决策核心的自主系统，经典组件包括：

- 规划（Planning）：任务分解、反思与自我批评
- 记忆（Memory）：短期上下文记忆 + 长期向量记忆
- 工具（Tools）：搜索、代码执行、数据库查询等外部能力
- 行动循环（Act Loop）：感知 → 思考 → 行动 → 观察结果 → 继续

多 Agent 系统把职责拆分给多个角色化的 Agent（如研究员 + 写手 + 审校），
通过共享黑板或消息传递协作，适合可并行的复杂任务。
